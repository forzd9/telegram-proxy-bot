# proxybot

بوت Telegram لإدارة قنوات مرتبطة به، وجمع قوائم بروكسيات عامة وفحصها ثم نشر النتائج وحفظ ملخصات الفحص. هذا الوصف مستند إلى ملفات المصدر وملف README الحالي في المستودع؛ لم يُشغّل البرنامج أو تُثبّت اعتمادياته، لذلك لا يُعدّ توثيقًا لتشغيل مُتحقَّق منه.

## ما يفعله المشروع

- يتيح للمستخدم ربط قناة بعد إضافة البوت إليها مشرفًا، ويحاول تسجيل القناة وربطها بحساب الشخص الذي أضافه. يحتاج النشر إلى صلاحية إرسال الرسائل في القناة.
- يعرض لوحة تحكم لاختيار القنوات وإجراء فحص يدوي، وعرض إحصاءات آخر جولة، وتفعيل الفحص الدوري أو إيقافه، وتغيير الفاصل الزمني إلى أحد الخيارات المتاحة في الواجهة (1 أو 2 أو 3 أو 6 أو 12 أو 24 ساعة)، وتنزيل آخر قائمة محفوظة أو إلغاء الربط.
- يقرأ مصادر بروكسي ثابتة من `config.py`، ويطلب قوائم من واجهة ProxyScrape، ويبحث عن ملفات قوائم إضافية عبر GitHub Search API.
- يستخرج عناوين على هيئة IP ومنفذ، ويضيف مرشحين بمنافذ شائعة إلى عناوين IP التي ظهرت في النتائج، ثم يحاول فحص المرشحين. يسجل الكود زمن الاستجابة وتصنيف الدولة عند توافره.
- ينشر النتائج الصالحة في القناة على شكل رسائل مجزأة أو ملف عند بلوغ حد داخلي، ويحفظ آخر قائمة وملخصات الجولات في SQLite.

الفحص ليس ضمانًا بأن البروكسي مجهول الهوية أو آمن أو سيظل متاحًا. كما أن وسم البروتوكول ونتيجة اختبار اتصال واحد لا يثبتان جودة البروكسي أو سلوكه في الاستخدام الفعلي.

## الملفات الرئيسية

| الملف | الدور الظاهر في المصدر |
|---|---|
| `bot.py` | معالجات Telegram، الواجهة، النشر ونقطة بدء الاستطلاع. |
| `config.py` | إعدادات البوت ومصادر البروكسي والفحص والتخزين. |
| `crawler.py` | البحث عن مصادر إضافية باستخدام GitHub Search API. |
| `scraper.py` | جلب النصوص واستخراج عناوين البروكسي. |
| `generator.py` و`engine.py` | توسيع المرشحين بمنافذ إضافية وربط مراحل الجمع والفحص. |
| `checker.py` | اختبار الاتصالات وجمع زمن الاستجابة ومعلومات الدولة. |
| `storage.py` | إنشاء قاعدة SQLite وإدارة القنوات والنتائج والقوائم. |
| `keyboards.py` | أزرار ولوحات التحكم. |
| `requirements.txt` | اعتماديات Python. |
| `Dockerfile` و`fly.toml` و`start.sh` | ملفات حاوية/نشر موجودة؛ لا تُعدّ دليلًا على إعداد نشر صالح أو مجرّب. |

## المتطلبات والإعداد

المصدر مكتوب لـ Python، وملف الحاوية يشير إلى صورة `python:3.12-slim`. لا يعلن المستودع مصفوفة توافق أصلية لإصدارات Python. تتضمن `requirements.txt` الاعتماديات التالية: `aiogram` و`aiohttp` و`aiohttp_socks` و`aiosqlite`.

تُظهر نقطة الدخول في `bot.py` تشغيل البوت عبر polling، ويمكن الاستدلال على خطوات الإعداد التالية من الملفات، لكنها **غير مجرّبة**:

```bash
git clone https://github.com/forzd9/telegram-proxy-bot.git
cd proxybot
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

قبل بدء التشغيل، راجع إعدادات `config.py`. أسماء الإعدادات ذات الصلة تشمل `BOT_TOKEN` و`OWNER_IDS` و`MAX_CHANNELS_PER_USER` و`GITHUB_TOKEN`. يعرّف المصدر هذه الإعدادات في الملف نفسه ولا يقرأها من متغيرات البيئة؛ لذا فإن الإشارة في README السابق إلى دعم `BOT_TOKEN` أو `GITHUB_TOKEN` عبر البيئة غير مثبتة في الكود الحالي. لا تضع أسرارًا في مستودع عام، ولا تنسخها إلى سجلات أو رسائل. يلزم نقلها إلى مخزن أسرار آمن وتعديل طريقة قراءتها قبل النشر.

بعد إعداد القيم اللازمة في نسخة محلية آمنة من `config.py`، نقطة التشغيل الظاهرة هي:

```bash
python bot.py
```

هذا أمر مستنتج من نقطة الدخول، وليس إثباتًا لنجاح التشغيل. لم يُختبر الإعداد أو البناء أو التشغيل أو أي من الأوامر.

## أوامر وواجهة الاستخدام

تُظهر المعالجات في `bot.py` الأوامر التالية:

- `/start` و`/channels`: عرض القنوات المرتبطة واختيار قناة.
- `/scrape`: بدء جولة جلب وفحص عند ارتباط قناة واحدة فقط بالحساب.
- `/stats`: عرض إحصاءات آخر جولة عند وجود قناة واحدة مرتبطة.
- `/auto_on` و`/auto_off`: تفعيل الجدولة أو إيقافها عند وجود قناة واحدة مرتبطة.

عند ارتباط أكثر من قناة، استخدم لوحة الأزرار لاختيار القناة وإدارتها. الفاصل الزمني يُختار من لوحة التحكم. قد يفشل إرسال رسائل التأكيد الخاصة إذا لم يبدأ المستخدم محادثة خاصة مع البوت أو تعذر مراسلته؛ لا تفترض أن التأكيد مضمون.

## التخزين والنشر

قاعدة البيانات الافتراضية هي `proxybot.db` في دليل العمل الحالي. تضم بيانات ربط القنوات وملخصات الجولات وآخر البروكسيات المحفوظة؛ لذلك يلزم تأمينها والاحتفاظ بنسخة احتياطية وفق الحاجة. في بيئة حاويات، لا تضمن الملفات الموجودة وحدها بقاء قاعدة البيانات بعد إعادة إنشاء الحاوية، ولا يعرّف `fly.toml` وحدة تخزين دائمة.

توجد ملفات Docker وFly، لكن لا يُنصح باعتبارها طريقة نشر جاهزة: `start.sh` يحاول بدء `dockerd` داخل الحاوية، بينما `Dockerfile` لا يثبت Docker daemon. كما أن README السابق يقترح خدمة systemd تعمل كمستخدم root دون أن يشرح معالجة الأسرار أو حماية قاعدة البيانات. لذلك لا أدرج هنا خطوات نشر إنتاجية؛ يلزم توحيد طريقة النشر، التحقق من التخزين الدائم والصلاحيات، ثم اختبار الإعداد في بيئة معزولة.

## تنبيهات أمنية وحدود

- تظهر إعدادات حساسة ثابتة في `config.py` بحسب الفحص. راجعها خارج README، وأبطِل/دوّر أي اعتماد سبق نشره إذا كان صالحًا، ثم انقله إلى آلية أسرار مناسبة. لا تُدرج قيمه في المستودع أو سجلات التشغيل.
- يجلب البرنامج بيانات من مصادر عامة وخدمات خارجية، منها GitHub Search API وProxyScrape، ويرسل طلبات اختبار عبر بروكسيات إلى خدمة اختبار IP ويطلب بيانات جغرافية من خدمة خارجية. تعامل مع مصادر البيانات والنتائج باعتبارها غير موثوقة، وراجع سياسات تلك الخدمات وخصوصية البيانات قبل الاستخدام.
- يجرّب مولّد المرشحين منافذ إضافية على عناوين ظهرت في القوائم. هذا نشاط اتصال/فحص لعناوين شبكية؛ لا تستخدمه إلا على أنظمة تملكها أو لديك إذن صريح بفحصها، والتزم بالقوانين وشروط الخدمات ذات الصلة.
- نشر قوائم البروكسي في قناة قد يعرّض متابعيها لخوادم مجهولة أو غير آمنة، كما أن صلاحية البوت للنشر قد تسمح بنشر محتوى غير مرغوب فيه عند إساءة الإعداد. استخدم قناة تملكها، وراجع النتائج قبل الاعتماد عليها.
- مهام الفحص تُنشأ كمهام خلفية، ولا يظهر في المصدر قفل يمنع تداخل الجولات المتزامنة. راقب الموارد والجدولة، ولا تفترض أن المهام ستُسلسل تلقائيًا.
- قاعدة SQLite محلية وليست خدمة نسخ احتياطي؛ فقد البيانات ممكن عند حذف الملف أو فقدان التخزين. كما أن سلوك تعطيل القناة عند تغيير الصلاحيات يحتاج تحققًا؛ لا تفترض أن كل فقد لصلاحية المشرف يُكتشف.
- المستودع لا يثبت مستوى أمان أو جاهزية إنتاجية، ولا يتضمن اختبارات موثقة في الملفات التي تمت مراجعتها.

## الترخيص

لم يُعثر على ملف ترخيص ضمن الملفات المتتبعة التي تمت مراجعتها؛ لذلك لا يُفترض ترخيص أو إذن إعادة استخدام.
